# 项目数据库

每个项目目录包含一份 `lunaria.db` 与素材。打开整个项目目录即可继续编辑；数据库中的素材路径相对于当前项目根目录，不记录原电脑的绝对路径。

## 文件与数据归属

- `<项目目录>/lunaria.db`：`project_meta` 保存项目名称、创建时间；`character`、`character_sprite_set`、`character_sprite` 保存作品内容。三张业务表不包含 `project_id`，角色与立绘组的关联保留。
- `<应用数据目录>/app.db`：`project` 保存本机最近项目索引，包括本机索引 ID、路径、展示名称、创建和最近打开时间。展示名称在打开项目时从项目库更新。

项目库中的 `project_meta.id = 1` 表示唯一元信息记录。各项目可以有相同的角色 ID 和角色 code。前端和业务命令中的 `projectId` 是本机最近项目索引 ID，用于核对当前打开的项目，不写入项目业务表。

## 创建与打开

1. 启动时打开 `app.db`；没有索引文件时建立空索引。
2. 新建项目时，先在项目目录创建完整数据库，再登记到本机索引。建库采用事务和同目录临时文件，校验并关闭后以不覆盖已有文件的方式发布。
3. 打开项目时验证文件标识、结构版本、必要业务列、SQLite 完整性与外键。缺少项目库、文件非法或版本不支持时返回错误，不自动创建替代文件。
4. 后端成功打开数据库后，前端才更新当前项目。每个业务操作使用同时绑定数据库和素材根目录的项目对象；切换后，新请求携带旧项目 ID 会被拒绝。

当前项目的内存状态位于 `src-tauri/src/state/project_state.rs`：`ProjectState` 保存唯一的 `CurrentProject`，其中 `db` 与 `info` 绑定项目数据库连接和项目信息；创建或打开成功后整体替换。Tauri 分别管理应用索引连接与当前项目状态，前端 Zustand 继续使用后端返回的项目信息展示界面。

数据库创建、打开与校验逻辑统一位于 `src-tauri/src/db/mod.rs`。表结构由 `entity` 定义，通过 SeaORM 的 `create_table_from_entity` 建表，再通过 `create_index_from_entity` 建立普通索引和联合唯一索引；不再单独维护建表 SQL。数据库以 `PRAGMA application_id` 标识格式，以 `PRAGMA user_version` 记录结构版本。`if_not_exists` 仅跳过已存在的表或索引，不会根据 entity 自动修改旧表；以后修改表结构时需提供对应升级步骤，当前只接受版本 1。

## 移动与复制

关闭项目后，复制或移动包含数据库与素材的整个项目目录，在新位置用“打开项目”重新选择文件夹即可。新电脑无需原来的应用索引；索引可从项目文件重新登记。

## 已完成的旧库转换

统一旧库已转换为项目独立数据库，一次性导入逻辑和迁移命令已删除。应用不会再读取旧 `lunaria.db` 或 `lunaria-legacy-backup.db`，也不会从它们重建最近项目索引。

原数据库和快照文件仍保留在应用数据目录，只用于人工恢复历史数据。它们不会同步新项目库的后续编辑，也不影响当前应用运行。

## 验证范围

Rust 测试使用真实临时 SQLite，覆盖新项目结构与约束、跨项目同号 ID 隔离、重开保留内容、目录移动复制、路径别名、非法或未来版本文件拒绝，以及旧库文件不再参与启动初始化。
